# Telegram A/B deeplink demo

Статический пример для `@my_super_super_puper_test_bot`, сборка `instant-navigation-8`.
Main App открывает `index.html`, именованный Mini App `launch` — `go.html`.
Сайт не использует bot token или backend. В репозитории находятся только публичные
настройки, код SDK и демонстрационные карточки A/B.

## Быстрый переход

Launcher подтверждает сохранение intent и сразу запрашивает открытие Main App.
Ожидания подготовки в 350 мс больше нет. Работающая сессия может готовить A/B в фоне,
но launcher не задерживает открытие ради этого подтверждения.

Ручные A/B меняют hash и DOM в одном обработчике, без анимаций и CSS-переходов.
Чтение новой цели и её применение отделены от очереди visible ACK: зависшее
подтверждение старой A не блокирует показ новой B. Счётчик и prepared-маркеры
также обновляются независимо от показа страницы.

Каждая HTML-страница включает публичную конфигурацию, SDK, shared и свой entry script.
После получения HTML отдельные загрузки скриптов и `config.json` не нужны.
JS-файлы сохранены отдельно для редактирования и проверки. Для старой страницы
без встроенной конфигурации shared сохраняет запасное чтение `config.json`.

Если native callback записи не приходит, точная проверка значения начинается
через 25 мс. До 250 мс повторное чтение планируется через 25 мс, далее через
250 мс. Одновременно выполняется не больше одного проверочного GET, SET не
повторяется; общий срок остаётся пять секунд. Ошибка SET останавливает переход.
Успех записи подтверждается только callback `true` или точным совпадением строк.

Обычный launcher не показывает промежуточную карточку. Через 600 мс при затянувшемся
переходе становятся видны статус, запасная кнопка и диагностика; ошибка раскрывает
их сразу. Этот таймер не задерживает открытие и не закрывает окно сам.
На холодном старте main не показывает промежуточную главную карточку до чтения цели.

Native анимация и выбор окна принадлежат клиенту Telegram. Код не может скрыть
нативную вкладку launcher или пробудить приостановленный WebView. Открытие закрытого
приложения также требует создания WebView. Мгновенность нативного переключения
не гарантируется; изменения убирают ожидания и анимации из веб-части.

## Сборка и публикация

После изменения JS, SDK или `config.json` выполнить из этой папки:

```sh
python3 build.py
```

Скрипт обновит встроенные блоки в `index.html` и `go.html`. Он не делает сетевых
запросов. Конфигурация может содержать только `botUsername`, `mainAppShortName`
и `launcherShortName`; секреты в неё добавлять нельзя.

Загрузить public-файлы в корень репозитория `telegram-deeplink-demo`, затем
Settings → Pages → публикация из корня main. Адрес:
`https://lan-pnz.github.io/telegram-deeplink-demo/`.

В BotFather настроить:

- Main App: `https://lan-pnz.github.io/telegram-deeplink-demo/index.html`.
- Direct Link `launch`: `https://lan-pnz.github.io/telegram-deeplink-demo/go.html`.
- Для канонического Main App оставить `mainAppShortName` пустой строкой.

Для launch и main нужен один бот. DeviceStorage локален для бота, пользователя
и устройства; требуется Telegram с WebApp API 9.0+.

## Проверка

Перед тестом полностью закрыть старые main и launcher, чтобы загрузить новую сборку.

1. При закрытом main открыть A: должна сразу появиться карточка A после загрузки.
2. Свернуть main и открыть B: должна появиться B. Сравнить ID основной сессии.
3. В main быстро нажать A → B → Главная: карточки меняются без эффектов и пауз.
4. Повторить ссылку A: новый clickId создаёт новую цель.
5. Обычный возврат без новой ссылки не должен повторять выполненную цель.
6. При сбое записи не должно быть открытия; ошибка и повторная попытка должны быть видны.

Ссылки:

- [A](https://t.me/my_super_super_puper_test_bot/launch?startapp=A)
- [B](https://t.me/my_super_super_puper_test_bot/launch?startapp=B)
- [Main App](https://t.me/my_super_super_puper_test_bot?startapp)

Для Android автоматическое открытие использует обычный HTTPS-переход на `t.me`,
ручная кнопка — `openTelegramLink` после нажатия в WebView. Этот путь основан на
ранее проверенных [исходниках Android 12.10.4](https://github.com/DrKLO/Telegram/blob/c84801762fd5f936c8296ecf09a14a48ebfc4fe4/TMessagesProj/src/main/java/org/telegram/ui/web/BotWebViewContainer.java#L1961).
Наличие native запроса не доказывает переход или выбор сессии на устройстве.

ACK записывается отдельно после видимого кадра, проверки свежей цели и маршрута.
Launcher закрывается по этому ACK либо по `deactivated` после сохранения и запроса
открытия. Prepared-маркер не потребляет pending и не заменяет ACK показа.
Фоновый WebView может не выполнить JavaScript до возобновления. Одновременные
launcher не имеют серверного атомарного упорядочивания; тестовые A/B не заменяют
авторизацию и контроль доступа настоящего приложения.

## Локальная проверка

```sh
python3 -m http.server 8766 --bind 127.0.0.1
```

На loopback без Telegram включается localStorage-симуляция. Она проверяет
JS-протокол, но не native DeviceStorage, фокус или скорость Telegram.
Диагностика не сохраняет и не выводит токен, initData, Telegram ID или данные профиля.
